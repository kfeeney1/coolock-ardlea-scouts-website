# SW-559 public Hall Hire

The approved public layout is served at `/hall-hire`, with the existing Group header/emblem and footer. Header navigation includes Hall Hire only when the independent rollout and server readiness projections are true. Off preserves existing public navigation and the route shows a contact action rather than an incomplete booking workflow.

The responsive hero links to an accessible monthly availability section. Month/day calculations reuse the SW-335 calendar utilities and theme tokens. Each day shows neutral occupied ranges (two previews plus count for additional ranges); selecting a day shows every occupied and complementary unreserved interval in a bounded scrollable region. Month navigation, Today and date buttons have accessible names, keyboard controls and visible focus. Out-of-month cells do not make availability claims. Dublin midnight, overnight projections and 23/25-hour clock-change days are handled as real time intervals. Display dates use the site's DD-MM-YYYY formatter.

Availability reads only `hallAvailability` documents for the displayed month, capped at 31 per request. It never queries private hall bookings, history, meetings, members or programme records. The decoder rejects unknown/private fields, invalid intervals and out-of-day slots. Missing day documents in a server-confirmed snapshot mean unreserved time; cached-only data, permission errors and malformed snapshots never become an apparently empty/free calendar.

The enquiry panel sits alongside the calendar on wide desktop and below it on mobile. It opens the user's email app with date/time details, using the same published Group email as the existing Contact page (`SITE_IDENTITY.publicEmail`). No new recipient, email service, website PII store or automatic email send is introduced. Both the panel and generated message state that an enquiry does not confirm a booking. Invalid dates/times disable the action. The Group confirms availability and hire arrangements separately.

No capacity, facility, address, accessibility, price, policy or hall photograph has been invented. Optional facts render only from a strictly public, explicitly confirmed `siteSettings/hallHireVenue` projection. Anonymous Rules deny unconfirmed documents or any document containing unknown/private fields. This projection is trusted-server-write only; no new client grant can publish facts. Supported fields: confirmed, name, introduction, facilities, address, accessibility, imageUrl and imageAlt. Images require HTTPS and descriptive alt text. In the absence of confirmed facts, the page invites users to ask the Group about facilities/access/hire arrangements and uses the established public contact; it does not display illustrative claims or imagery.

Readiness remains false until source integration and integrated acceptance are complete. Nothing is enabled or deployed by this PR. Rules/unit tests cover public facts/privacy, partial-day complements, contiguous occupancy, DST days, malformed data and enquiry semantics. Browser tests cover real neutral Firestore projections, private/unconfirmed data absence, month navigation, keyboard focus, 320px layout, disabled navigation and fail-closed availability errors. Physical Android, all-theme visual review and deployed Firebase TEST remain separate acceptance work.
